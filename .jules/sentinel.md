## 2024-05-18 - State-modifying API endpoints allowing GET requests
**Vulnerability:** CSRF vulnerability due to state-modifying endpoints (/api/cmd and /api/thresholds) allowing simple GET requests.
**Learning:** In simple ESP-based web servers, it is common to define routes without a specific HTTP method restriction. This allows unintended state changes via cross-origin GET requests.
**Prevention:** Always specify HTTP_POST as the method for state-modifying endpoints in the httpServer.on definition, and ensure CORS preflight OPTIONS requests are handled to support legitimate client applications.
## 2024-05-20 - CSRF via Wildcard CORS on Unauthenticated State-Modifying Endpoints
**Vulnerability:** CSRF vulnerability due to the combination of wildcard CORS (`Access-Control-Allow-Origin: *`) on state-modifying endpoints (`/api/cmd`, `/api/thresholds`) combined with a lack of authentication and CSRF token validation.
**Learning:** Even with HTTP method restrictions (e.g., `HTTP_POST`), simple requests (like POST with `text/plain` or `application/x-www-form-urlencoded` from a form submission) do not trigger CORS preflight. Therefore, relying solely on CORS wildcard headers without a custom header requirement leaves the endpoint vulnerable to simple cross-site requests.
**Prevention:** Implement strict CORS Origin validation against the Host header, local IPs, and `.local` hostnames. For state-modifying POST endpoints, enforce the presence of a custom header (e.g., `X-Requested-With: XMLHttpRequest`). This forces a CORS preflight from web browsers, which will be blocked by the strict CORS policy if the origin is untrusted, effectively preventing CSRF.
