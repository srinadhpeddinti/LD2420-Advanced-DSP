## 2024-05-18 - State-modifying API endpoints allowing GET requests
**Vulnerability:** CSRF vulnerability due to state-modifying endpoints (/api/cmd and /api/thresholds) allowing simple GET requests.
**Learning:** In simple ESP-based web servers, it is common to define routes without a specific HTTP method restriction. This allows unintended state changes via cross-origin GET requests.
**Prevention:** Always specify HTTP_POST as the method for state-modifying endpoints in the httpServer.on definition, and ensure CORS preflight OPTIONS requests are handled to support legitimate client applications.
## 2024-05-24 - Cross-Site Request Forgery (CSRF) via Overly Permissive CORS and Missing Headers
**Vulnerability:** The `/api/cmd` and `/api/thresholds` REST endpoints on the ESP8266 and ESP32 firmware were configured with `Access-Control-Allow-Origin: *` and did not require any custom headers to execute state-modifying actions. This allowed any website a user visited to execute cross-site request forgery attacks against the local device simply by issuing a `fetch()` POST request.
**Learning:** Returning `Access-Control-Allow-Origin: *` is extremely dangerous on local IoT devices, as it entirely bypasses the browser's Same-Origin Policy designed to protect them from external websites. Relying purely on the HTTP method (e.g., POST) is insufficient to prevent CSRF when CORS is wildly permissive.
**Prevention:** Always validate the `Origin` header dynamically against safe values (like `localhost`, the device's `Host` header, or valid local IP address ranges) instead of using `*`. Additionally, require a custom header like `X-Requested-With` on all state-modifying POST requests. Ensure `OPTIONS` handlers correctly echo the valid origin and permit the custom header.
