## 2024-05-18 - State-modifying API endpoints allowing GET requests
**Vulnerability:** CSRF vulnerability due to state-modifying endpoints (/api/cmd and /api/thresholds) allowing simple GET requests.
**Learning:** In simple ESP-based web servers, it is common to define routes without a specific HTTP method restriction. This allows unintended state changes via cross-origin GET requests.
**Prevention:** Always specify HTTP_POST as the method for state-modifying endpoints in the httpServer.on definition, and ensure CORS preflight OPTIONS requests are handled to support legitimate client applications.
## 2024-05-24 - [DOM-based XSS Prevention in Dashboard]
**Vulnerability:** Found `innerHTML` being used with template literals to construct HTML elements dynamically based on integer inputs (zones). Even though the input might currently be safe, this is a known anti-pattern for DOM manipulation which could lead to DOM-based XSS if the data source becomes tainted.
**Learning:** In a static HTML frontend that serves as a dashboard for an embedded device, relying on `innerHTML` for dynamic content generation is risky. It's crucial to use safe DOM APIs consistently.
**Prevention:** Avoid `innerHTML` entirely for dynamically generated content. Always use `document.createElement()`, `textContent`, and `appendChild()` to ensure data is treated strictly as text/nodes and never executed as markup.
## 2024-05-24 - [CI Compilation Failure Fix]
**Vulnerability:** CI workflow was failing because the relative path `./libraries/LD2420_Ultimate` in the `arduino/compile-sketches` action failed to resolve the local library, causing compilation to abort.
**Learning:** For the `arduino/compile-sketches` GitHub action, local libraries must be specified using an absolute path (like `${{ github.workspace }}/libraries/LibraryName`) for correct resolution, rather than a relative path, due to the execution context of the action runner. This aligns with existing memory about GitHub action behavior for local libraries.
**Prevention:** Always use absolute workspace paths for `--library` arguments in CI configurations to ensure consistent resolution.
## 2024-05-24 - [ArduinoJson v7 Upgrade Errors]
**Vulnerability:** The CI pipeline failed due to compilation errors related to `ArduinoJson` deprecations and namespace scoping issues in the custom firmware (`LD2420_AppLogic.hpp` and `LD2420_Pico_Ultimate.ino`). The CI environment appears to pull in a newer version of ArduinoJson (v7+) where `StaticJsonDocument`, `createNestedArray`, and `createNestedObject` are deprecated or removed in favor of `JsonDocument`, `to<JsonArray>()`, and `add<JsonObject>()`. Additionally, `TelemetryPacket` and `getTelemetryBinary` were not correctly placed within the `AppLogic` namespace in the header file, breaking their usage.
**Learning:** External dependencies in CI can drift and introduce breaking changes if versions are not strictly pinned (e.g., using `latest` for libraries in Arduino CLI). When dealing with library upgrades like ArduinoJson v6 -> v7, API deprecations can turn into hard compilation failures.
**Prevention:** Always follow the latest API guidelines for third-party libraries (like `ArduinoJson`) to ensure compatibility across versions. If possible, consider pinning critical library versions in CI configurations or `library.properties`.
